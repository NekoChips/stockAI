# StockAI 策略系统整体改造计划

## 1. 文档目的

本文档用于收敛当前系统与 [`2026-08-21-strategy-design.md`](../specs/2026-08-21-strategy-design.md) 中已确认的改造方案，作为后续实现、数据库迁移、测试和发布的执行依据。

本文档描述的是实施计划，不代表所有功能已经完成。实现过程中如需改变已经确认的业务规则，应先更新本文档并重新进行人工确认。

## 2. 最终业务边界

### 2.1 市场范围

- 交易和模拟成交仅允许沪深 A 股股票与 ETF。
- 允许的证券代码后缀仅为 `.SH`、`.SZ`。
- `.BJ`、`.HK`、`.US`、期货及其他市场数据只能作为分析因子或参考数据，不能进入持仓、下单和收益统计。
- 外部市场包括美股、韩股和期货，仅用于情绪、行业或风险分析。

### 2.2 默认观察池

- `588170.SH` 和 `588200.SH` 后续不再作为默认观察池标的。
- 删除代码配置中的默认种子，不自动删除数据库中已有的观察池记录、历史 K 线、成交、决策和日报数据。
- 已存在的两只 ETF 仍按普通观察池标的处理，用户可以在页面中删除。
- 删除前必须检查持仓和未完成订单；存在任一项时拒绝删除并提示原因。
- 删除后的标的可以重新添加，重新添加后恢复为“观察中、禁止交易”。
- 重新添加时优先复用已有历史数据；历史不完整时进入低优先级补数队列。
- 重新添加不会自动恢复交易权限，必须单独启用交易并经过人工确认。

### 2.3 账户与交易模式

- 单一模拟账户，初始现金为 1,000,000 元，初始无持仓。
- 系统只做模拟交易，不接入真实券商账号、真实资金或真实下单接口。
- 模拟成交、持仓估值和实际收益使用不复权价格。
- 技术指标、K 线趋势和回测使用前复权价格；原始价格、复权因子和派生价格分别保存。
- 除送转股外，不考虑现金分红和 ETF 分红分配。

## 3. 配置与策略版本管理

### 3.1 配置生效流程

所有策略、指标、权重、风控参数、仓位约束和标的绑定统一使用以下流程：

```text
保存草稿 -> 展示变更差异 -> 人工确认 -> 下一轮 monitor 生效
```

要求：

- 草稿、已确认、当前生效、已回滚状态可追踪。
- 一轮 monitor 只读取一次完整配置快照，保证本轮策略、风控和下单使用同一版本。
- 配置校验失败时整份拒绝，不允许部分生效。
- 已生效配置不可直接编辑，只能基于当前版本生成新草稿。
- 人工确认记录操作人、时间、版本号、变更说明和影响标的。
- 确认前展示仓位上限、策略权重、阈值、数据要求和潜在超限持仓变化。
- 支持撤回未确认草稿和回滚到历史已确认版本。

### 3.2 参数统一更新

代码默认值和数据库中的旧默认配置统一调整为以下基线：

| 参数 | 新基线 |
| --- | ---: |
| ETF 总仓位上限 | 50% |
| 个股总仓位上限 | 40% |
| 单只 ETF 上限 | 30% |
| 单只股票上限 | 30% |
| 组合总仓位上限 | 90% |
| 最低现金比例 | 10% |
| 单标的每日操作上限 | 10 笔 |
| 全局每日操作上限 | 不设置 |
| 单次加仓上限 | 组合净值的 10% |
| 买入/加仓信号阈值 | +0.60 |
| 减仓/卖出信号阈值 | -0.60 |
| 实时行情最大允许延迟 | 2 分钟 |
| 日 K、期货情绪、海外指数、龙虎榜最大允许延迟 | 1 个交易日 |

其中单标的每日操作上限支持页面配置。买入、加仓、减仓和卖出均计数；去重信号、未提交订单、风控强制清仓不计入普通操作额度。提交、拒绝和撤销的普通订单均计入操作次数。

数据库迁移时：

- 旧默认值统一替换为上述基线。
- 已有人工自定义配置不直接覆盖；若超出新的硬上限，标记为无效配置并生成待确认草稿。
- 新配置不能降低已有持仓后自动清仓，仅阻止继续买入或加仓。
- 新配置按照“草稿 -> 人工确认 -> 下一轮 monitor 生效”执行。

### 3.3 策略指标与组合

策略定义和指标名称使用中英文双语字段，例如：

- 技术综合策略 / Technical Composite
- 时间序列动量 / Time-series Momentum
- 均值回归 / Mean Reversion
- 相对强弱 / Relative Strength
- 期货情绪 / Futures Sentiment
- 海外市场情绪 / Overseas Sentiment
- 龙虎榜跟随 / LHB Follow
- 量化行业轮动 / Quantitative Sector Rotation

每个策略输出标准化 `-1.0` 到 `+1.0` 分数：

- `+1.00`：强烈看多
- `+0.75`：明显看多
- `+0.50`：轻度看多
- `0.00`：中性
- `-0.50`：轻度看空
- `-0.75`：明显看空
- `-1.00`：强烈看空

默认权重：

- ETF：技术 40%、海外/行业代理 25%、期货 15%、趋势/动量 20%。
- 股票：龙虎榜 35%、技术 25%、量化行业 20%、期货 10%、趋势/动量 10%。

第一阶段新增的期货、海外、龙虎榜和量化行业策略默认关闭；技术和趋势/动量策略继续运行。新增策略只有在数据完整、权重有效、策略已启用时才参与聚合。

规则：

- 启用策略权重必须有效且合计为 100%。
- 缺失的策略从本轮排除，剩余权重重新归一化。
- 有效权重不足 60% 时，组合信号失效。
- 实时行情或风控数据过期时，相关交易被禁止。
- 数据缺失视为该策略失效，不使用旧数据、代理值或人工猜测值补齐。
- 数据恢复后下一轮重新评估；人工禁用和风控锁定不因数据恢复自动解除。
- 股票与 ETF 可以分别绑定策略组合，不能强制所有标的使用同一套策略。

## 4. 具体策略建设

### 4.1 技术与量化策略

保留现有技术综合、趋势动量、均值回归和相对强弱能力，统一改为标准化评分，并接入数据库中的策略配置。

新增量化行业轮动策略，使用数据库中的行业分类、行业指数日线和龙虎榜统计，满足以下任意两项时形成行业信号：

- 20 日收益率位于行业前 30%。
- 5 日换手率位于行业前 10%，且满足数量不少于 3 只。
- 机构净买入数量不少于 2 只，或行业上涨比例不低于 60%。
- 个股换手率高于行业中位数。
- 个股位于行业强势排名前 30%。

### 4.2 期货情绪

- 使用 IF、IC、IM 期货数据。
- 默认权重：IF 30%、IC 35%、IM 35%。
- 中小盘和科技类标的重点参考 IC 与 IM。
- 数据频率为一个交易日。
- 仅用于分析，不产生期货持仓或期货订单。

### 4.3 海外市场情绪

- AlphaFeed 为主源，AKShare 为备用源。
- 美股和韩股数据按一个交易日同步。
- 在 A 股开盘前准备可用数据，交易时段不重复请求海外数据。
- 数据日期必须记录；超过一个交易日则该策略失效。
- 仅用于 A 股 ETF 或股票策略评分，不参与外盘交易。

### 4.4 龙虎榜策略

股票候选池只接收满足龙虎榜条件的股票，不因普通上市记录自动加入：

- 机构净买入不少于 3,000 万元。
- 明星席位净买入不少于 1,000 万元。
- 机构净买入占当日成交额不少于 5%。
- 机构买入与量化行业方向一致。
- 有效龙虎榜信号连续两个交易日出现。

排除涨停打开风险、接近跌停、低流动性、风险警示、停牌和数据超过一个交易日的标的。

龙虎榜候选有效期为 5 个交易日，超时未人工确认自动过期。人工确认后仅进入观察池，不自动开启交易。

明星席位采用 60 个交易日滚动统计，至少出现 5 次后计算：净买入 30%、T+1/T+3/T+5 胜率 25%、跟踪收益 25%、最大回撤 10%、稳定性 10%。达到胜率不低于 55%、平均跟踪收益大于 0、最大回撤不超过 15%、综合分不低于 60 且近期无失效记录时，才允许进入候选推广列表。

## 5. 行情数据、限流与缓存策略

### 5.1 数据源顺序

- 实时行情：AlphaFeed -> AKShare。
- 日 K：AlphaFeed -> AKShare -> 既有兼容备用源。
- 海外、期货、龙虎榜按数据集分别配置主备源。
- 每个逻辑批次只使用一个数据源，不跨源拼接同一批次字段。
- AlphaFeed 有效数据优先，AKShare 不覆盖已经接受的 AlphaFeed 记录。

### 5.2 AlphaFeed 限流

按 Free A 股套餐预留余量：

- 实时快照：每分钟最多 8 次，每次最多 5 个标的。
- 相邻请求至少间隔约 7.5 秒，保证至少一分钟内刷新一次。
- 日 K：每分钟最多 8 次，每次 1 个标的。
- 统一按接口类别共享限流器，避免不同调用路径叠加突破套餐限制。
- 实时行情优先级：持仓 > 已启用交易标的 > 普通观察标的 > 休眠标的。
- 休眠标的不请求实时行情，但保留日 K 同步。
- 当前持仓和已启用交易标的超过容量时，禁止继续启用新的交易标的并在页面告警。

### 5.3 主备切换与熔断

- AlphaFeed 失败 1 次后立即切换 AKShare。
- AlphaFeed 熔断 1 分钟，熔断期间不重试。
- 熔断结束只发起 1 次探测；成功恢复主源，失败继续退避。
- AKShare 失败后等待 15 秒并重试 1 次，仍失败则结束本轮，不进行紧密重试。
- 实时、日 K、龙虎榜、海外、期货等数据集独立熔断，互不影响。
- `market_quote_events` 保留 7 天，用于排查主备切换、限流和数据异常。

### 5.4 数据库读取优先

- 策略和页面默认只读取数据库。
- 实时接口只负责按调度刷新当前行情。
- 日 K、指数、行业和外部情绪按各自调度同步后入库。
- 观察池新增后优先查询数据库水位，只补齐缺失区间。
- 历史补数低优先级执行，交易时段暂停，不影响实时盯盘。
- 实时行情表按交易日保留当日分时数据；每日开盘前清理上个交易日的行情数据。
- 日 K 和业务历史数据长期保留。

## 6. Monitor 调度与执行链路

### 6.1 调度时间

- 09:05：同步交易日参考数据和外部情绪数据。
- 09:30-11:30、13:00-15:00：实时行情、策略评估、风控和模拟成交。
- 15:05-15:30：收盘同步、账户快照、日报生成、日 K 和基准补数。
- A 股非交易日不启动盯盘、不生成日报。
- 非交易时段进程休眠，不保持高频轮询；下一个交易时段再唤醒。

### 6.2 初始化

- 不再使用独立 bootstrap 容器。
- 初始化由 monitor 完成，包含证券目录、观察池历史 K 线、基准指数、交易日历和策略默认值。
- 观察池历史不足时禁止策略和交易，继续在后续轮次重试。
- 休眠标的仍继续同步日 K。
- MySQL 不可用时进入只读安全模式，禁止行情入库、策略、订单和持仓更新，页面展示最后一次持久化状态。
- monitor 当前按单实例设计，暂不增加多实例租约锁；保留后续扩展点。

### 6.3 单轮执行

1. 从数据库读取当轮完整配置快照。
2. 查询交易日历和交易时段。
3. 加载观察池、持仓、可卖数量、最新 K 线和最新行情。
4. 检查数据新鲜度和历史 K 线门槛。
5. 分别计算已启用策略评分。
6. 聚合策略评分并生成决策逻辑。
7. 先执行独立风控，再执行普通策略调仓。
8. 创建幂等信号和模拟订单。
9. 使用同一行情快照完成模拟成交。
10. 保存决策、订单、成交、持仓和账户快照。

每个标的每天只生成一条日报“决策逻辑”记录；同日多次评估和多笔成交合并到该记录的时间序列明细中，订单表仍保留完整订单事件。

## 7. 仓位、风控与模拟成交

### 7.1 仓位规则

- ETF 总仓位不超过 50%。
- 个股总仓位不超过 40%。
- 单只 ETF 不超过 30%。
- 单只股票不超过 30%。
- 组合总仓位不超过 90%。
- 最低现金比例为 10%。
- 有效上限取人工配置、资产类型上限和系统硬上限中的最小值。
- 新上限导致已有持仓超限时，不自动清仓；标记超限、禁止买入和加仓，仅允许减仓或风控清仓。

目标仓位映射：

- `+0.60`：达到单标的上限的 40%。
- `+0.80`：达到单标的上限的 70%。
- `+1.00`：达到单标的上限的 100%。

### 7.2 风控优先级

1. 强制清仓。
2. 组合回撤减仓。
3. 停止新开仓。
4. 普通减仓。

初始风控阈值：

- 单标的浮亏达到成本价的 -8%：清仓。
- 从持仓期间最高不复权价回撤 6%：清仓。
- 组合单日亏损达到 -3%：停止新开仓。
- 组合历史高点回撤达到 10%：将持仓降低至 50%。

风控强制订单未成交时标记为“风控待执行”，下一轮使用新鲜行情重试；普通操作被阻止，页面显示告警。手工取消必须填写原因，不能直接解除风控锁；只有条件不再成立时才允许通过草稿确认流程解除。

### 7.3 模拟成交

- 买入使用卖一价，卖出使用买一价。
- 买卖一价缺失时使用最新价并标记降级成交。
- 买入滑点 +0.05%，卖出滑点 -0.05%。
- 股票印花税 0.05%，ETF 不收印花税。
- 佣金 0.03%，最低 5 元。
- 最小交易单位 100 股/份。
- 当前 588170、588200 以及新股票默认 T+1；只有有明确规则证据且人工确认的 ETF 才允许 T+0。
- 未知结算规则时禁止交易。
- 订单状态：`pending -> submitted -> filled`，并支持部分成交、拒绝和撤销状态。
- 没有行情、停牌、涨跌停、资金不足或可卖数量不足时不得伪造成交。
- 每个信号只能关联一个订单，订单事件追加保存。
- 同标的同方向相同信号每天去重，距上次成交至少 5 分钟。
- 单标的每日最多 10 笔普通操作。

## 8. 观察池生命周期

状态建议：

```text
candidate -> observing -> trading_enabled -> dormant -> removed
```

- 龙虎榜候选 5 个交易日内未人工确认则过期。
- 人工确认候选后进入观察，不自动交易。
- 交易权限必须按标的独立开启，并单独确认。
- 连续 20 个交易日无有效信号的观察标的进入 dormant。
- dormant 不刷新实时行情，但继续同步日 K。
- removed 保留历史数据，不参与实时行情、策略和交易。
- 不允许添加已有标的，页面必须提示重复原因。
- 已有持仓或未完成订单时不允许删除标的。

## 9. 交易日历

统一使用一张交易日历表维护三套市场：

- A 股：`XSHG`，覆盖沪深交易日。
- 美股：`XNYS`。
- 韩股：`XKRX`。

数据源统一使用 `exchange_calendars`：

- 历史从 2020-01-01 开始，未来补齐 3 年。
- 首次全量同步，之后每日补充。
- 不在进程内缓存，每轮从数据库查询。
- 直接覆盖旧记录，保留来源版本、同步时间和变更日志。
- A 股非交易日不生成日报、不运行 monitor，也不记录停止原因。

## 10. 日报与页面

### 10.1 日报

- 取消 Markdown 日报，日报只写入 MySQL。
- 仅 A 股交易日收盘后生成。
- 无操作但存在账户时仍生成日报。
- 日报生成与账户快照、决策明细在同一事务中完成。
- 使用账户和日期幂等，重复执行不得生成重复日报。
- 日报只读，不允许修改、删除或人工改写。
- 支持按日期、标的、动作、订单状态和数据异常筛选。
- 分页查看，展开后展示成交和决策明细。

### 10.2 页面模块

新增或完善以下页面：

- 实时驾驶舱：实时持仓、最新价格、当日涨跌幅、仓位、可卖数量、浮动盈亏和执行状态。
- 盈亏分析：Agent 与上证指数、深证成指、沪深 300、创业板指、科创 50 对比；支持当年、当月和自定义区间，起始日收益率归零，图例可显隐。
- 盈亏日历：月/年切换，支持历史月份和年份，空日期补齐，收益额/收益率按钮切换。
- 决策轨道：持续观望状态最多保留一条或折叠展示，数据库同步压缩历史观望记录，其他记录分页或滚动展示。
- 策略中心：策略查看、双语指标、参数编辑、标的绑定、权重配置、草稿确认、版本差异和回滚。
- 日报归档：只读浏览每日账户、持仓、成交、策略评分、决策逻辑和异常。
- 标的详情：展示分时、五日、日 K、周 K、月 K 和重要分钟 K；在 K 线上标记买入、加仓、减仓、清仓和模拟成交，悬停显示操作摘要。
- 数据健康：显示主备源、限流、熔断、数据新鲜度、历史 K 线补数和 MySQL 状态。

页面保持桌面端和移动端兼容，过量内容使用分页、局部滚动和固定底部摘要，不能因数据量增长撑长页面。

## 11. 数据库改造

### 11.1 核心表

继续使用 MySQL 作为发布版持久化数据库，重点完善以下表或等价结构：

- `watchlist_items`：观察池当前状态、资产类型、交易开关和生命周期时间。
- `watchlist_exclusions`：删除记录和删除时间。
- `instrument_catalog`：全市场证券名称、代码、交易所和资产类型。
- `market_quotes`：当日实时行情分时记录和最新行情索引。
- `market_quote_events`：原始行情事件，保留 7 天。
- `bars`：原始日 K、分钟 K、前复权派生数据和复权因子。
- `trading_calendar`：三套交易日历统一表。
- `strategy_definitions`：策略和指标中英文元数据。
- `strategy_profiles`：按默认、资产类型和标的绑定的版本化配置。
- `strategy_change_log`：草稿、确认、回滚和操作审计。
- `decisions`：每轮决策和每标的每日唯一决策逻辑。
- `orders`、`order_events`、`fills`：模拟订单与成交链路。
- `portfolio_snapshots`：账户、持仓和净值快照。
- `daily_reports`：只读日报归档。
- `backtest_runs`、`backtest_candidates`：回测记录和候选策略。
- `data_sync_checkpoints`、`data_health_events`：同步水位、限流、熔断和异常。

### 11.2 关键约束和索引

至少需要保证：

- 每个账户、交易日、标的一条决策逻辑主记录。
- 每个交易日、标的、观察时间点的行情事件幂等。
- 每个策略配置版本唯一且状态流转合法。
- 同一信号幂等键不得重复创建订单。
- 日报按账户和日期唯一。
- 最新行情查询、按标的时间序列查询、日报归档分页、策略版本查询有对应索引。
- 行情事件按 7 天保留策略清理，其他业务历史不得误删。

## 12. 开发版、发布版与部署

### 12.1 开发版

- 开发版移除 SQLite 依赖。
- 本地验证使用确定性的 mock 数据和内存存储，不连接生产 MySQL。
- mock 数据应覆盖行情、K 线、数据缺失、主备切换、限流、成交、风控和报告场景。
- 测试数据每次运行可重置，不能依赖本机历史状态。

### 12.2 发布版

- 发布版使用 MySQL。
- 数据库连接通过环境变量或未提交的 `.env` 文件提供。
- 密码、AlphaFeed API Key 和其他敏感配置不得进入 GitHub、镜像层或示例配置。
- 继续使用 `docker-compose.yml`，镜像标签规则保持：
  - release 分支发布 `stockai:latest`。
  - 历史发布使用明确版本号，例如 `stockai:v0.1.3`。
- monitor 和 web 为长期服务；不再单独部署 bootstrap。

## 13. 数据迁移执行顺序

迁移脚本由项目提供，但生产执行由人工完成：

1. 停止旧版 monitor，确保没有写入事务。
2. 使用 `mysqldump` 在数据库所在主机或安装了 MySQL Client 的机器上备份数据库；不能把 `mysqldump` 命令粘贴到 MySQL SQL 控制台执行。
3. 校验备份文件可读、文件大小和表数量。
4. 执行结构迁移：新增字段、唯一约束、索引、策略版本字段、观察池状态字段和数据同步水位。
5. 执行数据迁移：
   - 将旧策略参数映射到新双语策略定义。
   - 统一写入新的仓位和操作上限默认值。
   - 将旧行情记录转换为新的交易日/观察时间字段。
   - 为现有观察池标的补齐 lifecycle 状态。
   - 不删除 `588170.SH`、`588200.SH` 的历史记录，只移除默认种子语义。
6. 运行迁移 dry-run，检查重复标的、重复日报、超限配置、无效策略权重和异常持仓。
7. 生成配置草稿，不直接切换 active 版本。
8. 在页面人工确认配置。
9. 启动新版本 monitor，由下一轮 monitor 读取新 active 配置。
10. 检查实时行情、历史 K 线、策略、模拟订单、持仓和日报。
11. 保留旧镜像和数据库备份，观察稳定后再清理。

回滚原则：先停止新 monitor，恢复数据库备份或回滚迁移脚本，再启动旧镜像。不得直接删除业务表或覆盖原始成交、日报和行情历史。

## 14. 回测与自我优化

- 回测只读取 MySQL 历史数据，不访问外部接口，不消耗实时额度。
- 使用点时数据，避免未来函数。
- 日 K 信号在下一个交易日开盘执行，盘中信号使用下一份可用快照。
- 手续费、滑点、T+1、涨跌停和可卖数量规则与模拟盘一致。
- 使用 walk-forward 验证，样本外数据至少 30%，历史至少 2 年。
- 至少 60 笔交易，验证集至少 20 笔。
- 候选策略相对当前策略收益至少高 2 个百分点，最大回撤不能恶化超过 1 个百分点。
- 每次最多搜索 500 组参数，最多保留 3 个候选。
- 风险上限不参与自动优化。
- 日内不自动修改参数；按日收集数据、按周回测候选、按月执行完整参数搜索。
- 回测结果只能进入候选草稿，不能自动替换当前策略。
- 候选策略必须人工确认，并在下一轮 monitor 生效。

## 15. 测试与验收标准

### 15.1 单元和集成测试

- 配置默认值与旧配置迁移测试。
- 588170/588200 不再作为默认观察池测试。
- 观察池添加、重复添加、删除、持仓删除拦截、未完成订单删除拦截、重新添加测试。
- 策略评分标准化、权重归一化、缺失数据失效测试。
- 仓位上限、现金下限、超限持仓禁止加仓测试。
- 单标的 10 笔限制和全局不限测试。
- T+1、T+0 资格和可卖数量测试。
- AlphaFeed 限流、主备切换、1 分钟熔断和数据集独立熔断测试。
- 实时行情当日保留、开盘清理、7 天事件保留测试。
- 交易日历三市场查询和非交易日 monitor 跳过测试。
- 日报单标的单日一条决策逻辑、幂等和只读测试。
- 回测不访问外部接口、候选需人工确认测试。

### 15.2 发布验收

- monitor 非交易时段休眠，交易时段至少一分钟内刷新一次。
- 页面实时持仓展示数据库最新行情和当日涨跌幅。
- 决策轨道不会因持续观望数据无限增长。
- 盈亏分析包含 Agent 和全部指定指数，图例可显隐，区间起始日归零。
- 日历支持历史月份、年份、收益额和收益率切换。
- 日报归档可按日期分页查看且不可编辑。
- 标的详情 K 线和模拟成交标记可正常加载。
- MySQL 重启或短暂不可用时进入安全模式，不产生错误订单。
- Docker 镜像可通过 `docker-compose.yml` 直接启动，敏感配置不在镜像中。

## 17. 完成定义

满足以下条件后，才认为本轮改造完成：

1. 代码默认配置中不再出现 588170/588200 默认观察池种子。
2. 旧参数已完成统一迁移，人工配置和新硬上限行为可验证。
3. 数据缺失不会触发策略交易，数据恢复后可自动重新评估。
4. AlphaFeed 调用不会突破已确认频率，失败时按规则切换 AKShare。
5. monitor 在非交易时段不进行无效轮询，交易时段能稳定运行。
6. 每个标的每天只有一条日报决策逻辑记录。
7. 回测候选不会自动改变生产策略。
8. MySQL 迁移可备份、可校验、可回滚。
9. mock 开发测试不依赖 SQLite、生产 MySQL 或外部网络。
10. Docker 镜像和页面功能通过发布验收清单。
