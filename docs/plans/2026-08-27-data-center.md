# 数据中心功能方案

**状态：** draft
**负责人：** product-and-platform
**创建日期：** 2026-08-27
**更新日期：** 2026-08-27
**关联：** [数据库数据字典](../architecture/2026-08-27-database-data-dictionary.md)、[行情数据表治理与 `bars` 淘汰实施方案](./2026-08-27-market-data-table-governance.md)、[实时快照与日 K 分时调度设计](../specs/2026-08-26-market-data-scheduling-design.md)

## 1. 方案结论

新增“数据中心”页面，定位为个人运维使用的数据观测与任务控制台，解决以下问题：

- 外部行情是否成功进入数据库；
- 当前数据覆盖到什么时间、是否存在缺口；
- AlphaFeed 与 AKShare 当前使用情况和最近切换情况；
- 数据是否满足策略、回测、详情页和收益分析的使用条件；
- 失败的同步任务如何重试，过期数据如何受控清理。

数据中心不是通用数据库后台。行情原始数据、复权数据、成交、订单、日报和审计事实均不提供在线逐行编辑功能；不提供任意 SQL 执行、任意表删除或任意字段修改。

## 2. 已确认的边界

### 2.1 使用者

- 仅供当前用户本人运维使用；
- 沿用现有服务访问控制，不新增复杂的多角色权限模型；
- 所有高风险操作仍需二次确认；
- 页面文案和状态全部使用中文，数据源、表名和策略指标保留必要的中英文标识。

### 2.2 操作记录

- 不新增“数据中心操作审计表”；
- 不记录每次点击、每次查询和每次清理的操作日志；
- 继续使用现有 `data_sync_status` 展示同步任务的最后状态、成功数、失败数和错误摘要；
- 数据表自身的 `created_at`、`updated_at`、`fetched_at` 等字段继续保留，用于判断数据新鲜度，不作为页面操作审计。

### 2.3 数据安全边界

允许的操作：

- 运行质量检查；
- 触发单标的或指定区间补数；
- 重试失败同步任务；
- 触发受控的数据清理；
- 查看数据样本和来源。

禁止的操作：

- 在线修改行情价格、成交量、时间和来源；
- 直接修改复权因子；
- 直接删除观察池日 K、指数日 K、分钟线、订单、成交和日报；
- 任意删除数据库表；
- 输入任意 SQL；
- 绕过策略数据完整性检查强行启用数据。

## 3. 数据范围与数据域

数据中心按照业务数据域展示，而不是简单按数据库表平铺。

| 数据域 | 主要表 | 页面职责 | 默认操作 |
| --- | --- | --- | --- |
| 观察池日 K | `bar_price_tracks` | 展示 raw、qfq、复权因子和历史覆盖 | 查看、质量检查、补数 |
| 指数日 K | `index_price_tracks` | 展示基准指数的覆盖和来源 | 查看、质量检查、补数 |
| 分钟线 | `intraday_bars` | 展示分时和分钟 K 的当日覆盖 | 查看、清理、补数 |
| 实时快照 | `market_quotes` | 展示当前交易日的最新行情和延迟 | 查看、质量检查、清理 |
| 行情采集诊断 | `market_quote_events` | 展示最近 7 天来源、切换和异常 | 查看、按保留期清理 |
| 同步任务 | `data_sync_status` | 展示行情、指数、目录和外部数据任务状态 | 查看、重试 |
| 标的目录 | `instrument_catalog` | 展示代码、名称、类型和同步日期 | 查看、全量刷新 |
| 交易日历 | `trading_calendar` | 展示 A 股、港股、美股覆盖情况 | 查看、刷新 |
| 外部市场数据 | `overseas_market_data`、`futures_positions` | 展示外部市场数据状态，明确不进入 A 股持仓和收益 | 查看、刷新 |
| 龙虎榜与辅助数据 | `lhb_records`、`lhb_seat_profile`、`lhb_quant_seats`、`instrument_sector_mapping` | 展示策略辅助数据的覆盖和新鲜度 | 查看、补数 |

数据中心不得把外部市场数据误显示为 A 股组合行情。页面需持续标注：**外部市场数据仅参与策略分析，永远不进入持仓和收益统计。**

## 4. 页面信息架构

### 4.1 顶部总览区

首屏展示当前系统数据健康度：

- 数据域总数；
- 正常、降级、失败的数据域数量；
- 最近一次成功同步时间；
- 最老未补齐的历史数据日期；
- 当前 AlphaFeed 状态；
- AKShare 备用状态；
- 待处理质量问题数量；
- 当前是否存在策略因数据缺失而失效的标的。

顶部只展示摘要，不把所有表的明细一次性加载进首屏。

### 4.2 数据域列表

每个数据域以紧凑列表项展示：

- 数据域名称；
- 关联表名；
- 当前状态：正常、部分缺失、同步中、降级、失败；
- 数据行数；
- 标的数量；
- 最早时间；
- 最新时间；
- 最近来源；
- 数据延迟；
- 质量问题数；
- 查看详情和可用操作。

数据域过多时使用分页或滚动容器，不能撑高整个页面。

### 4.3 数据详情抽屉

点击数据域后打开详情抽屉，不跳离数据中心。抽屉包含：

- 数据覆盖摘要；
- 按标的的覆盖列表；
- 缺失日期和断档；
- 来源占比；
- 最近失败信息；
- 样本数据预览；
- 质量检查结果；
- 补数、重试或清理操作。

原始数据样本默认只读，并限制返回数量，避免一次加载整张表。

### 4.4 数据质量面板

质量面板按严重程度分组：

- 阻断：会导致策略或页面不能安全使用；
- 警告：数据可用但存在覆盖或延迟问题；
- 提示：来源切换、近期清理或非交易日等信息。

每条问题必须显示数据域、标的、时间范围、问题类型、影响范围和建议动作。

### 4.5 同步任务面板

读取 `data_sync_status` 展示：

- 任务名称；
- 数据域；
- 最近开始和结束时间；
- 成功数；
- 失败数；
- 使用来源；
- 当前状态；
- 错误摘要；
- 重试按钮。

重试按钮只允许对失败或降级任务使用；运行中的任务不可重复提交。

### 4.6 数据清理面板

只展示符合既定保留策略的清理项：

- `market_quote_events`：保留 7 天；
- `market_quotes`：清理非当前交易日快照；
- `intraday_bars`：按交易日和保留策略清理；
- 过期目录或临时同步数据：仅在明确配置后清理。

清理前展示预计影响行数和时间范围，并要求二次确认。核心历史行情、订单、成交和日报不出现在清理列表中。

## 5. 数据质量规则

### 5.1 覆盖完整性

以 `trading_calendar` 为预期交易日基准：

```text
覆盖率 = 已有有效交易日数量 / 预期交易日数量
```

检查内容：

- 配置区间内是否存在缺失交易日；
- 最新数据是否达到应有日期；
- 是否存在连续断档；
- 观察池标的是否达到策略所需最小历史长度；
- 指数数据是否覆盖盈亏分析选择的区间。

缺失数据时沿用现有规则：策略数据视为失效，禁止该策略触发交易。

### 5.2 价格与字段合理性

检查：

- `open_price`、`high_price`、`low_price`、`close_price` 大于零；
- `high_price >= max(open_price, close_price)`；
- `low_price <= min(open_price, close_price)`；
- 成交量和成交额不为负；
- 时间戳按数据域单调递增且没有异常未来时间；
- raw、qfq、复权因子能够按交易日对应；
- 不复权价格用于持仓估值和实际收益，前复权价格用于技术指标和回测。

### 5.3 重复与唯一性

按目标表主键检查重复：

- `bar_price_tracks`：`symbol + interval_name + timestamp_value`；
- `index_price_tracks`：`symbol + interval_name + timestamp_value`；
- `intraday_bars`：`symbol + interval_name + timestamp_value`；
- `market_quotes`：`trade_date + symbol + observed_at`。

数据库主键冲突应通过幂等 upsert 处理，质量面板仍需报告重复输入或重复采集现象。

### 5.4 来源与新鲜度

展示并检查：

- 最近来源是 AlphaFeed 还是 AKShare；
- 是否发生过主备切换；
- 最近成功同步距当前时间；
- 交易时段实时快照是否超过允许延迟；
- 非交易时段日 K 是否在规定窗口完成；
- 失败是否达到熔断阈值。

数据中心不改变现有主备切换策略，只提供可解释的状态和手工重试入口。

## 6. 页面操作规则

### 6.1 补数

补数操作必须选择：

- 数据域；
- 标的或标的集合；
- 起止日期；
- 数据来源策略：默认主源优先、备用源兜底。

提交前展示预计范围和影响：

- 预计标的数量；
- 预计交易日数量；
- 是否需要同时请求 raw 和 qfq；
- 预计 AlphaFeed 请求量；
- 是否可能触发限流。

全量补数需要二次确认；重复提交同一范围时应被拒绝或提示已有任务运行中。

### 6.2 重试

重试只针对失败任务或失败标的，不默认扩大日期范围。重试前显示最近失败原因，包括：

- 网络错误；
- 主源限流；
- 主源返回空数据；
- 解析失败；
- 数据库写入失败。

### 6.3 清理

清理操作只能选择系统提供的保留策略，不能输入任意日期和表名。页面显示：

- 清理对象；
- 保留规则；
- 预计删除数量；
- 是否会影响详情页或策略。

### 6.4 质量检查

质量检查默认只读、可重复执行，不改变行情数据。检查结果直接返回当前状态，不新增操作审计记录。

## 7. 后端接口草案

接口命名以数据中心为边界，避免把多个数据域重新拼成一个超大接口。

```text
GET  /api/data-center/overview
GET  /api/data-center/datasets
GET  /api/data-center/datasets/{dataset}/summary
GET  /api/data-center/datasets/{dataset}/coverage
GET  /api/data-center/datasets/{dataset}/samples
GET  /api/data-center/quality
GET  /api/data-center/tasks
POST /api/data-center/quality/check
POST /api/data-center/tasks/{task}/retry
POST /api/data-center/backfill
POST /api/data-center/cleanup
```

接口要求：

- 每个接口只返回当前页面需要的数据；
- 列表、覆盖明细和样本数据分页或限制数量；
- 任务提交返回任务状态，不同步等待整段补数完成；
- 正在运行的同类任务需要幂等或明确拒绝；
- 不提供 SQL 参数；
- 不返回数据库密码、连接串、API Key 或内部凭据；
- 外部市场数据接口必须带 `external_only` 或等价语义，避免前端误归入 A 股收益。

## 8. 持久化与数据库方案

第一版不新增数据中心专用表，复用现有数据表和 `data_sync_status`：

- 数据量、时间范围和来源从目标行情表聚合；
- 质量检查结果实时计算；
- 同步状态读取 `data_sync_status`；
- 清理动作复用现有存储层方法；
- 任务执行状态沿用现有同步任务机制。

暂不持久化每次质量检查结果，也不持久化每次页面操作记录。后续如果需要绘制质量趋势，再单独评估 `data_quality_snapshots`，不能把质量快照混入行情事实表。

## 9. 分阶段实施计划

### 阶段一：后端聚合与接口

1. 增加数据域注册表和统一的数据域描述；
2. 实现总览、数据域摘要、覆盖范围和样本查询；
3. 接入 `data_sync_status`；
4. 增加数据质量规则服务；
5. 为补数、重试、质量检查和清理建立受控命令接口；
6. 在服务端限制范围、并发和危险操作。

### 阶段二：React 页面

1. 新增“数据中心”Tab；
2. 首屏只加载总览和数据域摘要；
3. 详情使用抽屉和分页，避免撑长页面；
4. 质量问题使用严重程度颜色和状态标签；
5. 使用统一的加载、空状态、失败和重试反馈；
6. 所有破坏性或高成本操作使用确认弹窗。

### 阶段三：联调与验收

1. 使用 Mock 数据覆盖正常、空数据、部分缺失、主备切换和失败场景；
2. 验证数据中心操作不会绕过策略数据失效规则；
3. 验证补数任务不会重复提交或扩大范围；
4. 验证外部市场数据不会进入持仓和收益接口；
5. 验证首屏不加载整张大表；
6. 验证移动端和桌面端列表、抽屉和确认弹窗可用。

## 10. 验收标准

- 能在一个页面看到所有外部数据域的当前状态；
- 能按数据域和标的查看行数、覆盖范围、来源和新鲜度；
- 能定位缺失交易日、断档、异常价格、重复输入和来源切换；
- 能对失败任务执行受控重试；
- 能对指定范围发起补数，并在提交前看到范围和限流风险；
- 能按既定保留策略清理允许清理的数据；
- 不允许页面修改核心行情事实或执行任意 SQL；
- 不新增操作审计表，不影响现有交易审计和数据同步状态；
- 数据中心接口不会返回全量大表，首屏加载不依赖所有明细接口；
- 观察池、指数、分钟线和实时快照继续使用各自的专用数据表；
- 数据中心显示的外部市场数据不会进入 A 股持仓和收益统计。

## 11. 暂待评审的问题

本方案进入实现前，需要重点评审以下问题：

1. 数据质量检查是否全部实时计算，还是需要增加质量快照表；
2. 补数任务是否直接复用现有同步任务，还是建立独立任务队列；
3. 分钟线的保留期是否沿用当前策略，还是在数据中心中增加可配置项；
4. 数据域详情是否需要展示更多原始样本字段；
5. 是否需要为数据中心单独增加访问入口开关。

在这些问题确认前，不开始修改数据库结构和正式页面。
