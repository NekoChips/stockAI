# 决策事件治理与摘要审计分离产品需求

**状态：** implemented
**负责人：** product-and-platform
**创建日期：** 2026-08-26
**更新日期：** 2026-08-26
**关联：** [决策事件审计分离设计](../design/2026-08-26-decision-event-audit-separation.md)

## 1. 背景

当前 monitor 每轮扫描观察池都会产生一条 `decision_events` 记录。对于连续观望的标的，这些记录的业务含义没有发生变化，却被全部写入日报的“决策与订单轨迹”，造成：

- 同一标的、同一状态在日报中重复出现；
- 阶段值 `decision` 直接暴露给用户，缺少业务语义；
- 日报详情接口返回大量无效重复数据；
- `decision_events` 没有明确的生命周期，长期运行会增加数据库、备份和维护压力。

本需求采用“摘要展示 + 原始审计分离”设计：日报面向决策复盘，审计明细面向排障和追溯，两者不再共用同一展示数据集。

## 2. 产品目标

1. 每个交易日、每个标的在日报主视图中最多展示一条最终策略摘要。
2. 连续的“观望”或“持有”不再重复占据日报列表。
3. 真实的订单状态变化和模拟成交仍然完整可追溯。
4. 当前阶段不保存每轮原始策略评估；未来如确有排障需求，再以独立审计表和分页视图扩展。
5. 所有内部事件阶段和状态都转换为用户可理解的中文文案。
6. 为策略事件、订单事件和日报摘要建立可执行的数据保留策略。

## 3. 非目标

- 本需求不改变策略计算公式、风控阈值或订单撮合规则。
- 本需求不删除日报归档能力。
- 本需求不允许通过前端隐藏重复数据来替代后端数据治理。
- 本需求不把外部市场数据或原始行情事件纳入 A 股持仓和收益统计。

## 4. 核心用户场景

### 4.1 收盘后查看日报

用户打开某交易日的日报，看到每个标的的最终决策、风控结论、目标仓位和汇总依据。连续观望的标的只出现一次，并能明确看到“未触发交易”的原因。

### 4.2 查看实际执行轨迹

用户需要确认某笔模拟订单经历了哪些状态时，可以看到“已创建、风控通过、已提交、已成交、已拒绝或已取消”等真实状态变化，但相同状态不重复展示。

### 4.3 排查策略或数据异常（未来扩展）

未来如启用原始审计，用户按日期、标的、事件阶段和时间范围打开独立审计明细。审计明细采用分页或游标加载，不与日报主列表混合。

### 4.4 长期运行维护

系统自动清理超过保留期限的业务事件，保留日报摘要和订单审计，页面或运维信息可以看到清理结果及当前数据量。

## 5. 功能需求

### P0：日报摘要治理

- 策略摘要唯一粒度为 `交易日 + 标的`。
- 日报主视图每个标的最多展示一条策略评估摘要。
- 摘要保留最终方向、是否通过风控、目标仓位、策略依据、约束和说明。
- 观望状态展示为“观望（未触发交易）”，持有状态展示为“持有（未触发调仓）”。
- 日报中的“决策与订单轨迹”更名为“策略与执行轨迹”。

### P0：业务事件分类

主列表只展示以下业务事件：

- 策略状态发生变化；
- 风控结果发生变化；
- 目标仓位发生变化；
- 订单状态发生变化；
- 模拟成交、拒单、撤单。

相同标的连续相同的观望、持有或风控结果，不新增主列表事件。

### P1：原始审计分离（预留，不在当前阶段启用）

- 原始审计如未来启用，必须独立于日报摘要查询。
- 支持按交易日、标的、阶段和时间范围查询。
- 默认分页加载，禁止一次性返回当天全部原始事件。
- 审计明细至少展示事件时间、标的、阶段、状态、策略 ID、订单 ID、原因和数据来源。
- 审计页面需要明确标识“原始评估记录”，避免用户将其理解为实际交易次数。

### P1：用户可读文案

| 内部值 | 页面文案 |
| --- | --- |
| `decision` | 策略评估 |
| `order` | 订单状态 |
| `观望` | 观望（未触发交易） |
| `持有` | 持有（未触发调仓） |
| `已创建` | 订单已创建 |
| `风控通过` | 风控通过 |
| `已提交` | 订单已提交 |
| `已成交` | 模拟成交 |
| `已拒绝` | 订单已拒绝 |
| `已取消` | 订单已取消 |

### P1：数据保留

- 未来原始策略评估事件（若启用）：保留 30 天。
- 订单状态和成交相关事件：保留 2 年。
- 日报摘要：长期保留。
- `market_quote_events`：继续保留 7 天。
- 清理任务按批次执行，不使用无条件全表删除。

## 6. 验收标准

1. 一个交易日内，同一标的的日报策略摘要最多 1 条。
2. 连续 100 次观望轮询不会在日报主列表产生 100 条记录。
3. 一笔订单的相同状态重复保存不会产生重复轨迹。
4. 页面不再直接显示 `decision` 英文阶段值。
5. 日报详情接口默认返回摘要和必要的执行事件，不返回全部原始轮询记录。
6. 原始审计支持分页，查询结果包含总量或下一页游标。
7. 清理任务可以按事件阶段执行，并记录成功、失败和删除数量；当前由 monitor 启动后的首次历史压缩及每日维护完成。
8. 历史重复日报经过迁移后，刷新页面不会再次出现同一标的的重复摘要。
9. 订单状态、成交数量和收益统计不因摘要去重而丢失。

## 7. 默认策略

本需求确认采用以下默认策略：

- 主视图优先可读性，按标的展示最终摘要；
- 当前不持久化每轮原始评估，只保留有业务意义的状态变化；未来若启用原始评估，必须不进入日报主视图；
- 未来若增加原始评估，业务事件和原始评估必须使用不同的查询与保留策略；
- 先治理写入和查询边界，再处理历史数据迁移；
- 历史数据清理必须先备份并提供可验证的迁移结果。
